# 图像素材路径

图像素材统一由应用数据目录管理。指令中的 `图像路径` 保存相对于 `DATA_FOLDER` 的完整子路径，例如 `images/游戏A/王国.png`；数据库字段、指令类型和工作簿结构保持不变。路径使用 `/` 保存，运行时兼容 Windows 的反斜杠。

## 选择、截图与保存

- 在参数编辑器选择外部图片时，将图片复制到 `data/images/`，不移动或覆盖源文件。工作区快捷截图、图像点击截图和后台快捷截图直接写入该目录。
- 已在数据目录中的图片保留原子目录。外部同名同内容的图片复用已有文件；同名不同内容的图片使用内容摘要作为文件名后缀，避免覆盖。
- 图片预览、前台识图、多图识别、等待、图片条件、OCR 图片输入和后台图像输入使用统一解析规则。后台截图输出、字库、工作簿等非识图输入不混入图像素材导入。
- 变量表达式保留到执行时再解析。缺失的旧图片保留原引用，供用户补齐或重新选择，不凭空生成错误的相对路径。

## 兼容旧项目

已有绝对路径仍可直接读取。旧路径失效时，先尝试将其中 `data/` 后面的完整子路径定位到当前数据目录；遗留的绝对路径和单文件名可从资源目录中查找唯一候选。遇到多张同名图片明确报错，不选第一张。新保存的带子目录路径不按文件名模糊替换。

相对引用优先从应用数据目录读取，同时兼容工作簿旁的旧相对资源和工作簿旁的 `data/` 资源。图片文件存在条件保留严格路径语义，不用其他目录里的同名图片代替目标。

导入明确选定的工作簿时，随工作簿携带的相对图片优先作为导入源。若它与本机数据目录中的同名图片内容不同，会复制为带摘要后缀的新文件，并更新导入的相对引用；不会误用或覆盖本机原图。

新增、编辑、Agent/批量写入、导入与导出工作簿时，现有可读取的图片引用统一转换为相对引用。不会在启动时批量改写用户数据库或原工作簿。工作簿导入先校验整体内容，数据库写入失败时回滚本次新复制的图片。旧版迁移预检使用临时素材目录，迁移包将图片放在自己的 `data/images/` 下。

## 搬迁与分享

Excel 仅保存路径，不嵌入图片。分享时同时携带工作簿和对应的 `data/images/` 目录；应用可从工作簿旁的 `data/` 导入图片。迁移整个应用数据时，保持数据目录内部结构不变。

默认源码数据目录为项目的 `data/`；Windows 成品遵循原数据目录规则，升级安装时位于可替换的 `current/` 外。环境变量 `ANCLICKER_DATA_DIR` 指定了其他目录时，该目录即所有相对图片引用的基准。

实现入口：`anclicker/platform/image_paths.py`；仓储在保存和工作簿边界执行导入，执行器只解析路径，不在运行中复制素材。

# 全功能规划、快速文件操作与截图 OCR 核验

Agent 读取功能栏当前注册表，包含新增的“其他 → 快速文件操作”和“本地OCR → 截图OCR核验”，共116项指令。所有指令名称和完整参数均可查询、生成草稿并由原执行器运行。注册表覆盖通过不代表小模型能正确理解任意说法，也不代表116项功能都做过真实环境验收；需要实际窗口、Excel、后台绑定、图像或账号的操作仍依赖相应环境。

## 使用方式

默认“试运行 → OCR 文字核验 → 草稿”。先生成候选步骤并预检核验条件，然后实际执行，截图后用 RapidOCR 识字，将识别文字交给当前模型判断。文字条件与模型判断均通过才自动加入可编辑草稿。失败或无法确认时弹出“是否将核验失败流程加入草稿？”，默认不加入；选择加入会标记核验失败，不会再次执行。试运行的操作不会因为拒绝入稿而撤销。

模型只读取文字，不理解图片；截图作为本机证据保留。打开明确目录、单文件复制、简单 CMD 创建目录和重命名可自动推导核验目标。其他操作请在最后一步给出完整窗口标题或区域、预期文字；没有核验条件时不试运行并显示失败提示。分支控制流程需先加入草稿后连接流程图。设置中仍可选择“仅生成草稿 · 不执行”，或“直接调用工具”。

明确路径的文件需求有确定性快捷通道，不依赖小模型重新改写路径：

- 复制 "C:/Work/a.txt" 到 "C:/Backup/a.txt"
- 打开 "C:/Work/report.txt"
- 检查窗口“report.txt - 记事本”是否显示“处理完成|结果正常”

前两条规划为快速文件操作。打开普通文件需与末尾核验步骤一起提出，目录打开和单文件复制可自动核验；核验步骤供模型验收使用，不额外放入操作草稿；仅生成草稿模式仍保留显式核验指令。复制目前处理单个文件，目标父目录必须存在；目录批处理仍使用功能栏“处理文件(白话)”等指令。

精确控制任意功能栏指令时可使用：

~~~text
使用获取时间 参数 {"变量":"当前时间"}
~~~

具体字段以 instruction_schema 为准。这类明确的 JSON 参数直接校验，不经模型重写。其他自然语言通过候选指令检索及完整参数定义生成计划；缺失必要信息时应补充后再执行。

## 快速通道

复制以参数数组直接调用 Windows 自带 robocopy.exe，不操作终端界面，不把路径拼进 shell 命令。先写暂存目录，确认退出码、源文件和副本 SHA-256 一致后提交目标。默认不覆盖已存在文件；可取消，取消前已提交的操作不会自动回滚。

打开使用 Windows 文件关联能力（ShellExecute）。仅收到打开请求不视为内容正确；需用窗口标题和预期文字继续核验。

## 截图 + OCR

1. 指定唯一、完整的窗口标题，或明确截图区域 x,y,w,h。
2. 窗口核验优先用 PrintWindow 获取指定窗口的真实画面，避免被其他窗口遮挡；不可用时才尝试置前截图。资源管理器额外核对实际路径。
3. 用本机 RapidOCR 识别刚保存的截图，按最低置信度过滤。长地址栏漏字时对原截图顶部重叠裁剪后再识别，保留裁剪图及原始证据。
4. 检查每个预期文字是否出现在一个识别框内；默认忽略大小写与空白，不使用模糊相似度冒充通过。
5. 保存 PNG 和同名 JSON 报告，包含文字、坐标、置信度、缺失项和 verified。Agent 展示截图、识别文本与核验状态。

默认最多尝试两次；未找到、模型缺失、窗口不唯一、截图被干扰或超时均不算通过。执行器“未通过时停止流程”默认开启。截图路径为 data/temp/agent-evidence。证据留在本机；API 返回路径与识别文字，当前不自动将图片上传到外部模型。

注意：OCR通过证明指定可见文字条件成立，不能证明按钮业务逻辑、数据库写入或远端事务完成；文件复制同时使用哈希判断内容一致。预期文字和目标区域应来自任务要求，不能将聊天框里的预期内容作为验证区域。

## CMD 资料与训练

来源：[Microsoft Learn Windows Commands](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/windows-commands)。

models/knowledge/cmd_index.json 保存757个官方命令及子命令链接，仅为索引，未逐条审核。cmd_reference.json 保存9个常用命令的中文用途、示例、注意点与源链接。cmd_reference 工具可离线查询。新增资料应先核实官方文档，再写训练样本；不要将网页中的文字当成待执行任务。

v2训练数据位于 models/training/data_v2，包含480条合成示例。命令示例、功能栏参数示例和OCR核验计划用于训练规划行为，不会在训练过程中执行这些操作。训练结果和能力限制记录在对应模型目录。

## 中文编号步骤

支持阿拉伯数字 1.、1、和括号编号，以及 一、二、和 第一步：第二步：。每个编号逐项解析，保留顺序和步骤备注；最多30项。编号重复、缺号或空步骤会报告错误。列表先完整规划，不会边规划边执行；随后按所选模式核验或加入草稿。直接工具模式中的编号任务仍按仅规划处理。

例如：

~~~text
1. 打开文件“C:/Work/report.txt”
2. 等待两秒
3. 按回车
4. 等待三秒
5. 检查窗口“report.txt - 记事本”是否显示“处理完成”
~~~

中文数字时长和明确的回车、文件、窗口核验句式由确定性解析处理；其他表达交给模型结合真实参数定义规划。若某步需要补充，整组不会部分写入。URL版本号和1.5秒等小数不会当成编号。

复查：.venv-build/Scripts/python.exe tools/check_chinese_steps.py

## 内部核验回归

`tools/check_draft_verification.py` 检查成功提交、失败确认/拒绝、禁止重复确认、取消、缺失条件和旧截图防护；截图匹配失败不能被模型的成功判断覆盖。模型返回格式错误、超时或证据不足均视为未通过。外部模型接口接收 OCR 文字，PNG 不自动上传。

## 常用文件夹自然语言

支持“打开桌面文件夹111”“打开桌面上的111文件夹”“打开桌面”“打开下载文件夹”等明确表达。通过 Windows 用户目录设置解析真实路径，不交给模型猜网址。不存在的目录明确报错；仅生成一条快速文件操作。打开目录后由资源管理器实际路径确认目标，再截图 OCR 匹配目录名称并交模型核验，不要求手填窗口标题。原句“打开桌面文件夹111”已真实通过路径、OCR和模型核验，自动入稿1条，证据见 verification/desktop-111-result.json。

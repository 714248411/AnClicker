## Windows Velopack 自更新

v1.3.2 恢复 Windows 托管版自更新。使用 `python packaging/build_velopack.py` 在本地构建并验收，默认产物目录为 `release/velopack`，目录须为空；再次构建可指定 `--output release/velopack-new`。脚本不上传、不发布。Python SDK 和本地 .NET `vpk` 工具均固定为 1.2.0，需要 .NET SDK。

验收通过后，将便携 ZIP 复制到产物目录的 `delivery/AnClicker-v1.3.2-Portable.zip`（版本自动取自 `CURRENT_VERSION`）。交付文件名遵循“程序名-v版本-Portable.zip”，复制通过 `.partial` 完成并核对大小和 SHA-256；同名交付文件不覆盖。Velopack 内部资产文件名及索引保持原样。

产物仅包含 Portable 绿色便携 ZIP、Full nupkg 和 `releases.win-x64.json`。传入 `--base 上一版本的full.nupkg` 可生成并验证增量包。`python packaging/smoke_velopack.py` 使用 `dist/velopack/AnClicker` 在 `build/velopack-upgrade` 下生成两个仅本地验证的包版本，验证下载、应用、重启和数据保留；不要发布这些测试包。

更新源为 `https://updates.ytsoftware.cn/an-clicker/win-x64`，公开配置统一位于 `info.py`，包标识为 `AnClicker`。2026-10-08 只读检查更新索引返回 HTTP 404；恢复代码和本地构建不代表线上已部署。

完整解压便携 ZIP 后双击根目录 `An Clicker.exe`，无需安装，不要单独移动任何程序文件。构建使用 `--noInst`，发现 Setup 或 installer 资产即验收失败。

托管版启动后后台检查和下载，准备好后点击标题栏右侧的“新版本”按钮。正在运行、录制、测试指令或存在未写入录制时不能重启。普通 ZIP 和源码不会自动更新，需先下载托管版。退出原程序，备份整个 `data` 后，将其复制到 Portable 根目录的 `data`（与 `current` 同级），目标已有数据时先单独备份并人工处理，不覆盖合并。也可用 `ANCLICKER_DATA_DIR` 指向原数据目录，禁止新旧程序同时使用。

托管版可写数据在 `current` 外；包中 `defaults` 只包含构建时生成的空白种子数据库。无写入权限时沿用 `%LOCALAPPDATA%/AnClicker` 回退。现有普通 ZIP 构建及其他平台发布方式保持不变。

本目录集中存放本项目的 PyInstaller spec 和打包说明。所有命令都应在项目根目录执行。

## 推荐命令

```text
python -m PyInstaller --clean -y packaging/main.spec
python packaging/build_release.py --version v1.0.0-beta.1
```

`packaging/main.spec` 使用 onedir 结构并按当前系统生成 `AnClicker.exe`、`AnClicker.app` 或 `AnClicker`。Windows 保持便携式 `data` 目录；macOS 和 Linux 首次运行时把种子数据库复制到系统用户数据目录。

macOS 和 Linux 必须在对应系统原生构建，不能从 Windows 交叉编译。仓库内的 Release 工作流会在三个 GitHub 托管运行器并行完成测试、构建、压缩和上传。

spec 会执行 `instructions.registry.hidden_imports()`，把注册表中的 32 个指令模块作为动态导入收集；同时递归包含各指令目录中的 `.ui`、生成的 `_ui.py` 和图片、样式、JSON 等静态资源。新增指令只需正确登记 `InstructionSpec`，不应再维护第二份 hidden imports 清单。

`old_ins` 是旧导航窗口和单体执行代码的只读参考归档。spec 不扫描、不导入也不复制该目录，运行时代码同样不得依赖它。

## Nuitka

如使用 Nuitka，只支持能在可执行文件同级保留外部 `data` 的 standalone 发布方式：

```text
nuitka --standalone --enable-plugin=pyside6 --plugin-enable=tk-inter --windows-icon-from-ico=clicker.ico --include-data-dir=flat=flat --include-data-dir=data=data --include-data-dir=instructions=instructions --include-package=instructions --include-package=pygments --include-package=pyttsx4 --remove-output main.py
```

不要直接使用 onefile 打包内嵌 `data`，临时解压目录中的配置和数据库无法作为持久化数据使用。

## 目录约束

- 不要进入 `packaging` 后执行命令，spec 中的路径统一从项目根目录解析。
- `build`、`dist` 是构建输出目录，继续位于项目根目录，不放入 `packaging`。
- `clicker.ico` 是应用图标，按参考项目结构保留在项目根目录。
- 打包前应运行注册表惰性导入检查，确认每个 `InstructionSpec` 的编辑器和执行器都能加载。
- 不要通过添加 `old_ins` 路径来解决缺失导入；应修复正式 `instructions` 模块或注册表。
